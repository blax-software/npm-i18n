# @blax-software/i18n

[![npm](https://img.shields.io/npm/v/%40blax-software%2Fi18n)](https://www.npmjs.com/package/@blax-software/i18n)
[![Node](https://img.shields.io/badge/node-%3E%3D18.17-green)](https://nodejs.org)

Per-page, all-locale translation sources for vue-i18n / Nuxt i18n, plus a CLI that
builds one message bundle per locale and fails CI when a key is missing.

## The source layout it works on

```
i18n/
  locales/en.ts         export default { common: { save: 'Save' } }
  locales/de.ts         export default { common: { save: 'Speichern' } }
  locales/pl.ts
  pages/cart.ts         export default { en: {...}, de: {...}, pl: {...} } satisfies TranslationFile
  pages/checkout.ts
  .messages/            generated by `blax-i18n build` (gitignore it)
```

Base files hold one locale each. Page files hold every locale side by side, so a
translator sees `en`/`de`/`pl` of the same screen in one place. The merged result
is `locales` seeded first, then every page deep-merged in path order (last wins).

## Install

```bash
npm install @blax-software/i18n
```

## Runtime API (`@blax-software/i18n`)

Framework-agnostic, no dependencies, safe in the browser.

```ts
import {
  TranslationMissing, type TranslationFile,
  mergeMessages, fallbackChain, createLazyLoaders,
} from '@blax-software/i18n'
```

| Export | What it does |
| --- | --- |
| `TranslationMissing` | The string `'[missing]'`. Put it where a translation is still open; `blax-i18n check` reports every occurrence. |
| `TranslationFile` | `{ [locale: string]: Record<string, any> }` — the page-module shape. Use `satisfies TranslationFile`. |
| `mergeMessages(locales, pages)` | `{ [locale]: messages }` — seed from `locales`, deep-merge each page's `[locale]` slice in order. Inputs are not mutated. Only locales present in `locales` are emitted. |
| `fallbackChain(locales, defaultLocale = 'en')` | vue-i18n `fallbackLocale` map: `{ de: ['en'], pl: ['en'], default: ['en'] }`. |
| `createLazyLoaders(loaders)` | `{ loadLocaleMessages(locale), hasLocaleBundle(locale) }` over static `import()` calls of the built bundles. |
| `checkTranslations(sources, { locales, reference? })` | The check logic on already-loaded data (what the CLI runs). `formatReport(report)` renders it. |

### Eager merge (Vite / Nuxt)

```ts
// i18n/messageloader.ts
import { mergeMessages } from '@blax-software/i18n'

const localeMods = import.meta.glob('./locales/*.ts', { eager: true, import: 'default' })
const pageMods = import.meta.glob('./pages/**/*.ts', { eager: true, import: 'default' })

const byPath = (mods: Record<string, any>) => Object.keys(mods).sort().map((p) => mods[p])
const locales = Object.fromEntries(
  Object.keys(localeMods).sort().map((p) => [p.replace(/^.*\/([^/.]+)\.ts$/, '$1'), localeMods[p]]),
)

export default mergeMessages(locales, byPath(pageMods))
```

```ts
// i18n.config.ts
import { fallbackChain } from '@blax-software/i18n'
import messages from './i18n/messageloader'

export default {
  fallbackLocale: fallbackChain(['en', 'de', 'pl']),
  messages,
}
```

### Lazy per-locale bundles

Run `blax-i18n build` (below), then load only the active locale:

```ts
// i18n/lazy-loader.ts
import { createLazyLoaders } from '@blax-software/i18n'

export const { loadLocaleMessages, hasLocaleBundle } = createLazyLoaders({
  de: () => import('./.messages/de.js'),
  pl: () => import('./.messages/pl.js'),
})
```

Leave the default locale out of the map and import it eagerly, so there is always a
complete fallback.

### Marking open translations

```ts
import { TranslationMissing, type TranslationFile } from '@blax-software/i18n'

export default {
  en: { cart: { title: 'Your cart' } },
  de: { cart: { title: 'Dein Warenkorb' } },
  pl: { cart: { title: TranslationMissing } },
} satisfies TranslationFile
```

## CLI (`blax-i18n`)

```
blax-i18n build [--src i18n] [--out <src>/.messages] [--locales en,de,pl] [--default en]
blax-i18n check [--src i18n] [--locales en,de,pl] [--default en] [--json]
```

- `build` writes `<out>/<locale>.js`, one `export default {...}` ESM module per locale.
  Sources are transpiled with esbuild, so `.ts` files need no bundler. `--default` is always emitted.
- `check` walks every key across the listed locales and reports, per locale, keys that
  are missing and values that still hold `[missing]`. Exit code 1 when anything is
  missing; `--json` prints the report object. Without `--default` the reference key set
  is the union of all locales; with it, that locale's keys (surplus keys elsewhere are
  listed as `extra` but do not fail the run).

```json
{
  "scripts": {
    "i18n:build": "blax-i18n build --src i18n --out i18n/.messages --locales en,de,pl",
    "i18n:check": "blax-i18n check --src i18n --locales en,de,pl"
  }
}
```

```
$ blax-i18n check --src i18n --locales en,de,pl
en: ok (312 keys)
de: ok (312 keys)
pl: 1 missing, 2 [missing] (311 keys)
  pages/account.ts  account.logout  missing
  locales/*  common.cancel  [missing]
  pages/cart.ts  cart.empty  [missing]
i18n check: 3 problems
```

Translation files are loaded as pure data: relative imports between them resolve,
`import { TranslationMissing } from '@blax-software/i18n'` resolves, any other import
yields `{}`.

## Node API (`@blax-software/i18n/node`)

`readSourceTree`, `buildMessages`, `writeMessages`, `checkSourceTree` and `loadModule`
are what the CLI calls; use them from a build script (for example a Nuxt hook that
regenerates bundles on change).
